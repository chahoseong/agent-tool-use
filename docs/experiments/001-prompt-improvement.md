# 프롬프트 개선 실험

## Summary

변경 대상을 판단하기 전에 필요한 정보를 조회하고 사용자 조건·정책과 대조하라는 지침을 추가했다. 공식 성공 횟수는 **4/12회에서 9/12회로 증가**했지만, 잘못된 대상 제안과 조회 누락은 남았다. 대상 판단이 일관되게 개선됐다는 근거는 얻지 못했다.

## Hypothesis

기존 `airline 42` 실행에서 다른 승객의 예약을 취소 대상으로 제안하고, 필요한 예약을 조회하지 않은 채 신규 예약을 제안하는 행동을 관찰했다.

**변경 제안 전에 조회할 정보와 대조할 조건을 명시하면, 조회 누락과 조건 오해로 인한 판단 오류가 줄고 필요한 변경을 정확하게 완료하는 데 도움이 될 것**이라고 예상했다.

## Setup

- **평가 대상:** `airline 42·41·22`, `retail 0`
- **실행 수:** task별 변경 전·후 각 3회, 총 24회. 실패한 실행도 포함했다.
- **Agent / User Simulator 모델:** Gemma 4 12B (QAT Q4_0)
- **평가 설정:** seed `42`, 동시 실행 `1`, 최대 step `200`, 최대 오류 `10`
- **비교 방법:** 공식 성공 여부(`reward = 1`), 실행 기록 분석, 저장된 기록에 대한 LLM judge 추가 채점을 함께 비교했다. Judge는 `gpt-6-astra(high)`를 사용했다.
- **변경 범위:** Agent 프롬프트에 지침을 추가했다.

Baseline 프롬프트는 다음과 같다. 두 버전 모두 뒤에 공식 도메인 정책을 전달했다.

```text
You are a helpful customer service agent.

Follow the policy strictly. Use the provided tools to help the user.
```

변경 버전은 위 문구와 도메인 정책 사이에 다음 지침을 추가했다. 특정 task의 정답이나 예약 ID는 포함하지 않았다.

```text
Before proposing changes, use the available tools to retrieve the records needed to identify the correct targets. Check those records against the user's requirements, exclusions, and the policy. Do not conclude that a relevant record is absent, or expand the scope of work, based on information you have not checked.
```

## Results

[근거 자료 안내](../../artifacts/published/README.md)에서 task별 대화·도구 호출, 공식 결과와 추가 채점 근거를 확인할 수 있다.

### 공식 채점

저장된 공식 검사 결과를 버전별 3회씩 합산했다. 모든 값은 변경 전 → 후 순서다.

- **Read / Write:** 기준에 명시된 조회·변경 도구 호출 중 도구 이름과 비교 대상 인자가 일치한 건수 / 검사 건수. Agent의 전체 호출 수가 분모인 것은 아니다.
- **DB:** 최종 DB 상태가 기대 상태와 일치한 실행 수 / 전체 실행 수.
- **공식 성공:** 최종 `reward = 1`인 실행 수/전체 실행 수.

| Task                 | Read           | Write      | DB         | 공식 성공  |
| -------------------- | -------------- | ---------- | ---------- | ---------- |
| **airline 42** | 23/24 → 23/24 | 4/6 → 5/6 | 0/3 → 2/3 | 0/3 → 2/3 |
| **airline 41** | 19/24 → 24/24 | -          | 3/3 → 3/3 | 3/3 → 3/3 |
| **airline 22** | -              | 3/9 → 2/9 | 1/3 → 1/3 | 1/3 → 1/3 |
| **retail 0**   | 12/12 → 12/12 | 0/3 → 3/3 | 0/3 → 3/3 | 0/3 → 3/3 |

### 행동 관찰

| Task                 | 실행 기록에서 확인한 내용                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **airline 42** | 필요한 두 예약만 취소한 실행은 늘었다. 그러나 타인 예약을 실제로 취소한 실행은 전후 1/3로 같았고, 잘못된 제안과 조회 누락도 남았다.                   |
| **airline 41** | 취소 없이 DB를 유지했다. 전체 예약 조회는 2/3 → 3/3으로 늘었지만, 최종 거절 사유가 사용자에게 전달된 실행은 1/3 → 0/3으로 줄었다.                   |
| **airline 22** | 요청한 세 변경을 모두 완료한 실행은 늘지 않았다. 승객 정보 변경을 완료한 실행은 2/3 → 1/3으로 줄었다.                                                |
| **retail 0**   | 올바른 두 상품 선택은 전후 3/3으로 같았고, 교환 접수는 늘었다. 변경 전 세 실행은 모두 사용자 동의와 함께 시뮬레이터가 대화를 종료해 접수 전에 끝났다. |

### 추가 채점

[행동 평가 기준](../decisions/002-supplementary-evaluation.md)에 따라 공통 항목 5개를 채점했다. 아래는 **통과 횟수/통과·실패로 판정된 실행 수**의 변경 전 → 후 비교다. 버전별 전체 실행은 각각 3회이며, 해당 없음(N/A)은 분모에서 제외했다. `—`는 세 실행 모두 해당 없음이고, 판단 불가 판정은 없었다.

| Task                 | 조회 근거  | 제안 적절성 | 사용자 동의 | 요청·정책 준수 | 안내 정확성 |
| -------------------- | ---------- | ----------- | ----------- | --------------- | ----------- |
| **airline 42** | 2/3 → 0/3 | 0/3 → 0/3  | 2/2 → 3/3  | 1/3 → 2/3      | 0/3 → 0/3  |
| **airline 41** | 2/3 → 0/3 | 1/2 → 0/2  | -           | 2/3 → 0/3      | 1/3 → 1/3  |
| **airline 22** | 2/3 → 2/3 | 0/3 → 1/2  | 1/2 → 1/1  | 0/3 → 2/3      | 1/3 → 1/3  |
| **retail 0**   | 3/3 → 2/3 | 3/3 → 3/3  | 3/3 → 3/3  | 1/3 → 1/3      | 1/3 → 2/3  |

`retail 0` Baseline의 사용자 동의 3/3은 명시적 동의가 있었던 실행 기록을 근거로 정정한 값이다. [원래 판정과 정정 근거](../../artifacts/published/corrections.json)를 함께 보존했다.

`airline 42`는 공식 성공이 늘었지만 조회 근거의 통과는 줄었고, 제안 적절성·안내 정확성은 전후 모두 통과하지 못했다. `airline 41`도 공식 성공은 유지됐지만 추가 채점의 여러 항목이 악화됐다. 공식 성공 증가와 행동 기준 충족이 함께 개선된 것은 아니다.

### 결론

**조회·대조 지침을 프롬프트에 추가했지만, 목표로 한 대상 판단의 일관된 개선은 확인하지 못했다.** 공식 성공 횟수는 4/12 → 9/12로 증가했으나, 추가 채점과 실행 기록은 판단 과정이 함께 개선됐음을 보여주지 못했다.

주요 개선 대상인 `airline 42`에서는 타인 예약을 실제로 취소한 실행이 전후 1/3로 같았고, 추가 채점의 조회 근거 통과는 2/3 → 0/3으로 줄었다. 제안 적절성과 안내 정확성도 전후 모두 0/3이었다. `airline 41` 역시 공식 성공은 유지됐지만 추가 채점의 여러 항목이 악화됐다. `retail 0`은 상품 선택과 동의 획득이 전후 모두 이루어졌으며, 교환 접수 완료의 차이는 대화 종료 여부와 함께 관찰됐다.
