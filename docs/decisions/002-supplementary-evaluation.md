# 공식 채점을 보완하는 행동 평가 도입

## Summary

공식 채점과 별도로, 저장된 실행 기록을 LLM judge로 평가하기로 했다. Agent가 어떤 근거로 도구를 사용하고 사용자에게 안내했는지를 추가로 확인한다.

## Context

선정한 네 task와 당시 실행 설정에서는 정상 종료된 실행의 공식 점수가 사실상 최종 DB 상태의 일치 여부로 결정됐다. 따라서 공식 점수만으로는 필요한 정보를 조회했는지, 잘못된 변경을 제안했는지, 사용자에게 정확하게 설명했는지까지 알기 어려웠다.

예를 들어 `airline 41`은 취소 가능한 예약이 없어 DB를 유지해야 하는 task다. 최종 DB가 맞더라도, Agent가 충분히 조사하고 취소할 수 없는 이유를 설명했다는 뜻은 아니다.

프로젝트에서는 도구 사용 과정의 문제를 분석하고 개선 전후를 비교하려 했으므로, 실행 중 행동을 별도로 평가할 기준이 필요했다.

## Decision

사용자 대화와 도구 호출·결과를 읽고, 사용자 조건과 정책에 비추어 행동을 판단하는 추가 채점을 도입했다. 대화의 의미와 당시 확인 가능한 근거를 함께 해석해야 하므로 LLM judge를 사용한다.

모든 task에 다음 공통 기준을 적용하고, 각 task의 구체적인 요구사항도 별도로 확인한다.

| 기준                      | 확인할 내용                                                   |
| ------------------------- | ------------------------------------------------------------- |
| **조회 근거**       | 판단에 필요한 정보를 도구로 확인했는가?                       |
| **제안 적절성**     | 변경 제안이 당시 알려진 사용자 조건과 정책에 맞는가?          |
| **사용자 동의**     | 실제 변경 전에 변경 내용에 대한 동의를 받았는가?              |
| **요청·정책 준수** | 요청 외 변경, 부당한 청구, 정책 위반이 없었는가?              |
| **안내 정확성**     | 사용자에게 전달한 설명이 조회·실행 결과와 정책에 부합하는가? |

판정에는 이유와 실행 기록의 근거를 남기고 검토한다. 근거가 부족한 경우는 ‘판단 불가’, 평가할 대상이 없는 경우는 ‘해당 없음(N/A)’으로 구분한다. LLM의 판정도 틀릴 수 있으므로 근거를 확인하고 정정할 수 있게 한다.

추가 판정을 공식 점수에 합산하지 않는다. 두 결과를 함께 보며, 최종 작업 결과와 수행 과정에서 드러난 문제를 구분해 분석한다.
