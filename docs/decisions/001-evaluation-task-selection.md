# 평가 Task 선정

## Summary

Agent의 개선 전후를 비교할 평가 대상으로 `airline 42·41·22`, `retail 0`을 선정했다. 대상 판단 오류를 관찰한 `airline 42`를 중심으로, 다른 작업에서도 필요한 판단과 처리를 유지하는지 함께 확인한다.

## Context

Mock에서 기본적인 도구 사용 흐름을 확인한 뒤, 더 복잡한 사용자 조건과 정책을 다루는 task에서 분석할 문제를 찾았다. 기존 `airline 42` 실행에서는 다른 승객의 예약을 취소 대상으로 제안하고, 필요한 예약 조회를 누락한 채 신규 예약을 제안하는 행동을 관찰했다.

이 문제를 개선하더라도 다른 상황에서 불필요한 변경을 하거나, 필요한 작업까지 거절·누락할 수 있다. 따라서 문제를 발견한 task와 함께 비교할 평가 대상을 정해야 했다.

## Decision

다음 네 task로 평가 범위를 정했다.

| Task                 | 선정 이유                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **airline 42** | 문제를 발견한 사례다. 여러 예약에서 변경할 대상과 유지할 대상을 구분하고, 조회한 사실을 사용자 조건과 대조하는지 확인한다.                  |
| **airline 41** | 조건과 정책을 확인한 결과, 취소할 수 있는 예약이 없는 사례다. 필요한 조사를 하고 변경하지 않아야 한다는 판단을 설명하는지 확인한다.         |
| **airline 22** | 승객 정보·좌석 등급·수하물을 변경해야 하는 사례다. 신중하게 판단하라는 지침이 필요한 변경까지 거절하거나 누락하게 만들지 않는지 확인한다. |
| **retail 0**   | 사용자 조건과 재고에 맞는 두 상품을 골라 교환을 요청하는 사례다. 다른 도메인에서도 조건 대조와 필요한 처리를 유지하는지 확인한다.           |
